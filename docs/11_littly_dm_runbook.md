# 인스타 자동 DM — ManyChat → 리틀리(litt.ly) 이전 런북

> 작성일: 2026-08-15
> 대상: `@caselab_ai_` 댓글 키워드 → 자동 DM → 숏링크 유입
> 배경: **ManyChat 무료 플랜이 2026-03-02부터 1,000 → 25 액티브 컨택트로 축소**되어 실사용 불가.
> 리틀리는 인스타 DM 자동화를 **무료 플랜에 개수·기간 제한 없이** 제공한다.
>
> 관련: `/admin/marketing`(유입 링크 대장) · `components/admin/MarketingLinkForm.tsx` · 본가 `/l/{code}` redirect handler

---

## 0. 이전해도 되는 이유 — 결정 변수 검증 완료

우리 구조는 **DM 본문 버튼 → `caselab-five.vercel.app/l/{code}` → 본가가 클릭 적재 후 UTM full_url로 302** 다.
따라서 "DM 버튼에 임의 외부 URL을 넣을 수 있는가"가 이전 가능 여부를 가르는 유일한 변수였다.

리틀리 자동화 4단계 화면에 선택지가 둘:

| 옵션 | 상태 |
|---|---|
| 내 리틀리에서 선택하기 | **(준비중)** — 비활성 |
| **링크 URL 직접 입력하기** | ✅ `연결 URL` 자유 입력 (`https://`) |

→ 우리 숏링크를 그대로 넣을 수 있고, `/admin/marketing` 클릭 집계는 **손대지 않아도 그대로 작동한다.**

## 1. 준비물 체크

| 항목 | 확인 |
|---|---|
| Instagram 계정 | `@caselab_ai_` |
| 계정 유형 | **프로페셔널** — 카드뉴스 발행 때문에 이미 전환됨 (`docs/10_instagram_connect_runbook.md` 1단계) |
| 공개 여부 | **공개 계정이어야 함** — 비공개면 연동 자체가 막힌다 |
| ManyChat 상태 | **댓글 자동화를 실제로 운영한 적 없음** (2026-08-15 사용자 확인) — 옮길 자산이 없다 |

> 페이스북 페이지는 **필요 없다.** 리틀리는 Instagram 공식 로그인(Instagram API with Instagram Login) 경로를 쓴다.
> 카드뉴스 발행이 쓰는 `graph.facebook.com` 경로와는 별개 체계다.

**이건 "이전"이 아니라 "신규 구축"이다.** ManyChat에서 베껴올 키워드·문구가 없으므로
게시물·키워드·DM 문구를 처음부터 정해야 한다 (5단계에서 다룬다).
ManyChat 쪽 뒷정리는 7절 — 할 일이 거의 없다.

## 2. 리틀리 가입

1. https://start.litt.ly → **무료로 시작하기** (실제 가입 주소: `https://app.litt.ly/register`)
2. 이메일+비밀번호 또는 소셜 계정
3. 리틀리 페이지는 **대충 만들고 넘어가도 된다.** 우리는 DM 자동화만 쓰고 리틀리 페이지는 노출하지 않는다.
   (무료 플랜은 페이지 1개 + 리틀리 로고 노출 — 안 쓸 거라 무관)

---

## 3. 인스타 계정 연동

관리 페이지 → **[마케팅] 탭** → **인스타 DM 자동 발송** (카드에 "100% 무료 이용 제공" 표기)

1. **계정 연동** 클릭 → Instagram 공식 로그인 팝업
2. 권한 허용 화면에서 리틀리(`Littly-IG`)가 요청하는 항목:

   - 프로필 조회 및 미디어 액세스 **(필수)**
   - 댓글 액세스 및 관리
   - 메시지 액세스 및 관리
   - **콘텐츠 액세스 및 게시**
   - 인사이트 액세스 및 관리

> ⚠️ **게시 권한까지 넘어간다.** 리틀리가 우리 계정에 글을 올릴 수 있는 권한을 받는다는 뜻이다.
> 기능상 필요해서 요구하는 묶음이지만, 알고 승인할 것. 나중에 인스타 설정 →
> 웹사이트 권한에서 언제든 회수할 수 있다.

3. 연동 완료 후 **카드뉴스 발행 토큰이 멀쩡한지 확인**:

```bash
cd "apps/caselab_admin"
node scripts/instagram-connect.mjs --verify
```

별개 앱·별개 토큰이라 영향이 없어야 정상이지만, 5초면 끝나니 한 번 돌린다.
`❌`가 뜨면 `docs/10_instagram_connect_runbook.md` 3~4단계로 토큰만 다시 뽑으면 된다.

## 4. 숏링크 먼저 준비 (DM에 넣을 링크)

자동화를 만들기 **전에** 링크가 있어야 한다.

먼저 `/admin/marketing` 표를 열어 **쓸 만한 행이 이미 있는지 확인한다.**
(과거에 숏링크만 만들어 두고 자동화는 안 걸어둔 상태일 수 있다. 있으면 그 행의 **[복사]** 를 눌러 재사용 —
클릭 누적치가 이어진다.) 없으면 새로 만든다.

### 새로 만들기
`/admin/marketing` 상단 폼:

| 필드 | 값 |
|---|---|
| target URL * | 최종 목적지 (예: `https://caselab-five.vercel.app/tools/...`) |
| 트리거 키워드 * | 댓글 키워드 (예: `자료`) — campaign으로도 자동 저장됨 |
| 인스타 게시물 URL | (상세 옵션) 어느 게시물에 건 자동화인지 대장용 |
| 플로우 | (상세 옵션) 폼 라벨은 "ManyChat 플로우"지만 그냥 자동화 이름을 적으면 된다 |

**[숏링크 생성]** → 나오는 `https://caselab-five.vercel.app/l/xxxxxx` 복사.

## 5. 자동화 만들기 (5단계 마법사)

**[+ 무료 자동화 만들기]** 버튼 → 5단계 진행.

### 1단계 — 게시물 선택
연동된 계정의 게시물 썸네일 목록에서 자동화를 걸 게시물을 고른다.

### 2단계 — 트리거 키워드
- **모든 댓글**에 발송 / **특정 키워드 포함 댓글**에만 발송 중 선택
- 유사 의도 키워드를 한 자동화에 묶으면 포착률이 오른다: `자료` `신청` `링크` `주소`
- (블로그 FAQ 기준) **팔로우 여부 체크** 옵션이 있어, 팔로워에게만 보내거나 팔로우를 유도하는 DM으로 분기할 수 있다

### 3단계 — DM 메시지 + 버튼
- **메시지 입력*** — DM 본문
- **버튼 입력*** — 버튼에 표시될 문구 (예: `자료 받기 📄`)
- 상단에 실제 DM 모양 미리보기가 뜬다

> ⚠️ **버튼은 1개 구조로 보인다** (메시지 1 + 버튼 1 + 링크 1).
> ManyChat에서 버튼을 여러 개 쓰고 있었다면 링크를 하나로 합치거나 자동화를 나눠야 한다.
> 실제 화면에서 [+ 버튼 추가]가 있는지 먼저 확인할 것.

### 4단계 — 링크 연결 ★ 핵심
`DM버튼 클릭시 연결될 링크를 설정해주세요`

- ○ 내 리틀리에서 선택하기 **(준비중 — 비활성)**
- ● **링크 URL 직접 입력하기** ← 이걸 선택
- `연결 URL *` → **4단계에서 복사한 `https://caselab-five.vercel.app/l/xxxxxx` 붙여넣기**

> 리틀리 페이지를 거치지 않으므로 유입 추적 주체는 계속 우리 DB(`link_clicks`)다.

### 5단계 — 댓글 자동 답글
`게시물 댓글에 대하여, 자동 답글을 남길까요?`
- 아니오, 괜찮아요! / 네, 답글을 남기고 싶어요
- 남긴다면 짧게: `DM 보내드렸어요! 확인해 주세요 📩`

**완료** → 자동화 목록에 행이 생기고 상태 토글이 **ON**.

## 6. 검증

목록 행에 **전송수 / 읽음 / 클릭** 컬럼이 찍힌다. 실제로 한 바퀴 돌려본다.

1. **본인 계정이 아닌 다른 인스타 계정**으로 해당 게시물에 트리거 키워드 댓글 작성
   (본인 계정 댓글은 자기 자신에게 DM이 안 가서 테스트가 안 된다)
2. 몇 초 안에 DM 도착 확인 → **무료 플랜이면 리틀리 홍보 문구가 함께 붙어 온다** (실물 확인해둘 것)
3. DM의 버튼 클릭 → 목적지 페이지로 정상 이동하는지
4. `/admin/marketing` 새로고침 → 해당 행의 **클릭 (7일)** 이 +1 되었는지 ← **이게 최종 확인**
5. 리틀리 자동화 목록의 **전송수/클릭**도 올라갔는지 (양쪽 숫자가 대체로 맞아야 정상)

4번이 안 오르면 숏링크를 잘못 붙였거나 `is_active`가 꺼진 것이다. 대장에서 상태 토글 확인.

## 7. ManyChat 뒷정리 — 할 일 거의 없음

**댓글 자동화를 실제로 걸어둔 적이 없으므로 중복 발송 위험이 없다.** 리틀리 세팅을 먼저 끝내고,
ManyChat은 나중에 편할 때 정리하면 된다. 순서를 지킬 필요도 없다.

### 먼저 딱 하나만 확인 — 결제 중인지

**Settings → Billing**

- **Free 플랜이면 아무것도 안 해도 된다.** 그냥 두면 된다 (자동화가 없으니 DM이 나갈 일도 없다)
- **유료 결제 중이면 바로 해지한다** — 안 쓰는 데 돈이 나가고 있다는 뜻이다
  1. **Cancel Subscription** → 해지 사유 선택 + 간단한 설명 → **Next** → **Cancel My Subscription**
  2. **Pending cancellation** 으로 바뀌고 현재 결제 주기 끝에 완전 해지 (그때까지 유료 기능 유지)
  3. **다음 결제일보다 며칠 여유를 두고** 할 것 — 타임존·결제 처리 지연으로 한 달 더 빠지는 사고가 흔하다

### 계정 연결까지 끊고 싶으면 (선택)

리틀리가 안정적으로 도는 걸 2주쯤 확인한 뒤에 해도 늦지 않다.

- **되돌릴 수 있는 쪽**: Settings → **Instagram** → 맨 아래 **Disable Instagram Channel**
- **영구**: 같은 화면 맨 아래 **Remove Instagram Account from Manychat** → 체크박스 2개 → `Remove` 타이핑 → Confirm
  - Remove 버튼은 **계정 소유자에게만** 보인다 (Settings → Team Members에서 확인)
  - 인스타 컨택트가 영구 삭제되지만, 애초에 자동화를 안 돌렸으니 지울 컨택트도 없을 것이다

> ⚠️ 인스타 설정에서 ManyChat **앱 권한을 먼저 끊으면** ManyChat UI가 반쯤 끊긴 상태로 남아
> Remove 버튼이 안 뜨는 사례가 보고된다. ManyChat 안에서 먼저 정리하고, 인스타 권한 회수는 마지막에.

### 참고 — 나중에 자동화를 실제로 만들었다면

리틀리와 ManyChat이 **같은 게시물**에 동시에 켜져 있으면 DM이 두 번 간다.
그때는 `Automations` → `My automations` → 필터 **Has active triggers + Post or reel comment** →
트리거에 마우스 올려 나오는 **토글로 OFF** (꺼지면 `Off` 태그).

## 8. 운영 중 주의

| 항목 | 내용 |
|---|---|
| 워터마크 | 무료 플랜 DM에 리틀리 홍보 문구가 붙는다. 제거는 **브랜드 플랜 월 9,450원**뿐 — **프로(2,450원)로 올려도 안 없어진다** |
| 멀티 계정 | 인스타 계정 2개 이상 연결도 브랜드 플랜 전용. 계정 1개면 무관 |
| UTM·GA4 | 리틀리 UTM 기능은 프로부터지만 **우리는 불필요** — `/l/{code}`가 이미 UTM 붙은 full_url로 302한다 |
| Meta 정책 | 댓글은 "사용자가 먼저 행동"이라 정책상 안전. **24시간 안에 응답**하는 형태를 유지할 것 (즉시발송이므로 자동 충족) |
| 발송 실패 | 상대가 DM 수신을 제한해 뒀거나 계정 상태에 따라 조용히 실패할 수 있다. 전송수 대비 읽음이 지나치게 낮으면 의심 |
| 권한 회수 | 인스타 비밀번호 변경·권한 회수 시 연동이 끊긴다. DM이 갑자기 안 나가면 3단계 재연동 |
| 코드 라벨 | `MarketingLinkForm.tsx:103,128`에 `kind:'manychat'`, `medium:'manychat'`이 하드코딩. 동작에는 지장 없지만 UTM medium이 사실과 달라진다 — 아래 참고 |

## 9. (선택) admin 코드 라벨 정리

지금은 숏링크가 전부 `utm_medium=manychat`으로 나간다. 실제로는 리틀리를 쓰게 되므로 분석 라벨이 어긋난다.
급하지 않지만 정리하려면 두 군데:

- `components/admin/MarketingLinkForm.tsx` — `medium` 기본값(`:40`, `:128`)과 `kind`(`:103`)
- `app/admin/marketing/page.tsx:31` — 목록 조회 필터 `.eq('kind', 'manychat')`

> ⚠️ `kind`를 바꾸면 **기존 행이 목록에서 사라진다** (필터가 안 맞아서). 값을 바꾸려면
> 기존 행 마이그레이션이 같이 필요하다. **가장 안전한 선택은 `kind`는 그대로 두고
> `medium`만 선택형으로 빼는 것**, 또는 라벨이 거슬리지 않으면 아무것도 안 건드리는 것.
